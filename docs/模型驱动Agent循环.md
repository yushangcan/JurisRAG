# 模型驱动的法律检索 Agent

日期：2026-10-17。此版本把模型从“检索结束后归纳”移到循环的决策位置。SQLite、父子切块、官方来源元数据和只读查询继续复用，没有新增运行依赖。

## 从一次请求理解执行过程

用户问“供应商资格条件与证明材料分别有哪些”。规则先提供最低争点与待查法源提示；模型选择查询与精确查找参数，程序执行检索，把候选交回模型。模型再选择父证据ID读取正文，判断是否已经覆盖资格条件和证明材料。仍有缺口时可以再次搜索，充分时提交带引用的结构化陈述；也可以请求用户补充事实或拒答。

控制循环位于 `agent/loop.py`，HTTP 入口仍调用 `agent/service.py::run_agent`。模型每一步通过同一个 `AgentDecision` 协议返回动作；这是结构化 JSON 决策与程序工具分发，不依赖供应商原生 function calling 或 LangGraph。

## 五种动作

| type | 模型填写 | 程序执行 |
| --- | --- | --- |
| search | 1～3条 queries、可选 references、可选新增 issues | 调用现有检索器，返回精确与BM25融合候选 |
| read_evidence | 已观察到的父 evidence_ids | 从同一 SQLite 读取真实父法条 |
| answer | claims，每条有 text、quote、evidence_id、issues | 核验后组成正式回答 |
| clarify | 需要补充的事实问题 | 返回 needs_clarification，不附正式法律引用 |
| refuse | 当前不能回答的原因 | 返回 refused，正式引用为空 |

每次决策都能看到用户问题、规则提示、候选片段、已读正文、先前搜索/读取动作、最近工具观察和剩余预算。回答校验失败时，还会看到具体错误与被拒陈述，从而修正引文、删去无依据数字或继续补查。程序不要求输出或保存模型内部思维链。

模型上下文中的候选按父证据去重，最多20条，每段摘要最多300字符；已读父证据最多10条，总正文按每条最多6000字符和总量预算截取，并显式标记是否截断。数据库与正式引用仍保留完整父证据，不能把模型看到的节选当作完整法律审查。

## 模型与程序各自负责什么

模型负责理解语义、补充遗漏争点、选择查询、评估证据相关性与适用条件，并综合解释。初始规则给出最低检查要求；模型可以增加争点，不能通过覆盖计划删掉已有要求。

程序核验用户明确指定的法规引用，以及已有场景映射的最低法源要求。对于没有场景法源映射的问题，模型循环不使用原问题0.34词项覆盖阈值否决同义表达；由模型判断相关性，程序继续检查引文和生成陈述。

正式回答的证据必须已通过工具读取；任意猜测的ID和仅出现于候选摘要的ID不能直接引用。最多返回 top_k 个父证据。每个争点必须被陈述标记覆盖，陈述所引ID必须真实，引文需与原文匹配，数字与期限必须出现在本条引文中。原文实际援引的其他法条允许照录，模型额外编造的法规引用仍会被检查。

争点标记、字面覆盖和法规映射均不是语义蕴含证明；模型也可能遗漏争点、误读条件或选错版本。循环提供纠错机会，不能保证减少所有检索错误或产生正确法律结论。

## 停止、降级与预算

默认配置为：3次搜索、8次模型决策、单次20秒、总请求120秒、2个并发请求。读取和提交回答都消耗模型调用预算，搜索与模型决策分别计数。环境变量上限为6次搜索、12次模型调用、单次60秒、总请求300秒、8并发。

重复搜索/读取动作不会再次执行；连续两次搜索没有新候选时停止；预算耗尽时不会将尚未通过校验的回答提升为正式答案。总超时保留已发生的模型用量并清空正式引用；底层同步请求可能继续到自身超时，取消协程不代表撤销供应商计费。

兼容模型接口发送 `response_format={"type":"json_object"}`，仍由Pydantic验证动作字段；不靠修补括号接受损坏JSON。输出无法解析或不符合动作Schema时，在剩余调用预算内允许一次格式重发；连续两次失败才回退。其他模型调用失败直接在剩余搜索预算内回到规则检索与原文展示，并附警告。已在模型循环中发生的调用和搜索保留计数。端点不支持JSON输出约束时也会明确回退。没有配置模型、或显式 model=None/ENABLE_LLM=false 时执行离线规则流程。精确法条原文查询继续零模型调用；含“解释、分析、关系、适用”等请求的指定条号问题进入模型流程。

响应的 `agent_trace.controller` 会区分：

| controller | 含义 |
| --- | --- |
| llm_loop | 模型实际参与动作选择，包括主动澄清、拒答或预算停止 |
| rule_workflow | 显式离线或未配置模型 |
| rule_fallback | 模型决策失败后执行规则回退 |
| exact_reference | 指定法条原文快速路径 |
| fixed_rag | 固定一轮RAG，可选一次模型归纳 |

`decision_steps` 统计模型决策次数，`iterations` 统计搜索次数。每次模型调用记录供应商返回的Token；缺失时为null。模型循环成功回答时 `generation_mode=agent_llm_loop`，模型主动请求事实时为 `agent_llm_clarification`。

## 验证与评测解释

`tests/agent/test_model_loop.py` 使用真实冻结语料和可控模型动作，验证主动补查、错误反馈后的修正、未读取证据拦截、争点不可删除、重复动作、搜索/调用预算和澄清。`tests/test_llm_transport.py` 通过本地兼容HTTP端点执行搜索→读取→回答，验证真实传输、引用及供应商Token读取。

旧的30题和50题报告属于规则版本开发回归，不能直接作为模型循环的成绩。离线评测继续显式使用model=None；启用 `--with-llm` 后分别记录每题的controller、动作、决策步数、搜索次数和真实用量，降级不计作模型循环成功。仍需独立题集和答案质量评审才能比较检索、推理与成本。

本轮真实模型路径、受控遗漏、早期失败与修复后结果见 [模型循环验收记录](模型循环验收记录.md)。

运行方式见项目 README；本机已有 `.env` 需设置 `ENABLE_LLM=true`，配置已有供应商，并更新模型/搜索预算。密钥只保留本机，不提交仓库。
