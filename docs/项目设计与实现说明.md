## 存储与更新

SQLite 的 documents 表保存文档元数据，nodes 表同时保存 parent 与 child，search_index 保存子块的标题和正文 token，info 保存文档计数、向量配置与快照哈希，user_version 标记格式。

法条型原文按完整条文生成父块，通知、附件按原有章节结构生成父块，长父块再切子块。检索只对 child 排名，回答前按 parent_id 回填完整原文。引用包含法规名、条号或章节、页码、来源及证据 ID；/api/v1/evidence/{id} 可读取完整父证据。

原文须与 manifest 或转换报告的 SHA-256 匹配；Markdown 须与冻结摘要、front matter 的原文哈希一致。转换质量检查与法律内容审核分开：摘要只能证明文件未被意外改变，不能证明法律时效。构建临时 SQLite 通过完整性检查后替换正式文件，任何失败不覆盖旧库。

## 检索与覆盖

第一轮包括用户问题、匹配场景的查询和法源位置。BM25 多查询按倒数排名融合；正式条号匹配给予确定性优先级。只指定文档名的场景还需达到内容覆盖阈值，不能拿同一文件任意一段证明所有争点。

每轮累计结果按证据 ID 去重，并更新更好的得分。明确引用逐条满足；不同争点分别核验。制度不明且场景涉及两套法源时，两套分别进入待查争点。超过6个争点或8处正式引用时请用户拆分，不静默删除多余要求。

若缺口仍在，规则构建补查查询；启用模型时最多一次改写。查询按规范化集合计算签名，避免原样重复。没有新证据、正式法源缺失、预算耗尽等均终止。最终父条先覆盖争点，再补高分结果，之后重新核验。上下文不足则清空正式引用。

一般问题的词项覆盖只是保守启发式门槛。场景映射本身也需要持续人工复核；它们无法形式化证明证据完整或法律适用。

## 模型归纳

调用可选模型前先得到可引用父证据。模型只能输出 claims，每条包括 text、evidence_id、quote。检查 ID 是否属于本次证据、引文是否为真实连续原文、陈述与引文的内容覆盖、数字和法规引用，以及部分绝对化或缺事实的结论。失败直接展示原文，没有重复生成和模型自审循环。

验证通过也同时展示引用原文。该机制减少部分可检测错误，不保证陈述语义与法律推理正确。每次模型调用记录供应商、模型名、耗时、成功状态、异常类型和供应商实际返回的 Token；缺失值为 null，不保存请求或回复正文。

## 请求状态与运行边界

answered 表示通过当前证据门；needs_clarification 表示缺少法规名称或项目事实；refused 表示当前无法提供足够依据。拒答永远不附正式引用。缺事实但一般规则充分时允许引用，并明确尚不能裁断具体项目。

并发保护是进程内的；多 Uvicorn worker 各有独立额度。总体等待超时会停止等待并取消协程，保留已发生的模型调用记录。底层同步网络/检索线程不能被 Python 强制终止，模型 HTTP 另设 socket 超时和响应大小限制；不能把协程取消描述成已撤销外部模型计费。

服务默认本机监听，无账户隔离和认证。对外部署需受控入口。可选 hybrid 的向量扫描是 O(Nd)，仅为当前小语料提供简洁实现。健康检查验证文件、索引与依赖存在，不预加载推理会话，实际推理能力仍需查询验证。

## 测试与结果解释

测试使用临时目录，从同一批真实冻结语料建库，不改用户索引。重点覆盖双法源、条号缺失、追问、补检、重复终止、后轮证据替换、最终上下文不足、原文与模型降级、用量、总超时、HTTP 契约、损坏索引和原子入库失败。

默认环境不装 MCP，其协议测试跳过；安装可选依赖后验证真实内存 MCP 会话。轻量环境不包含向量库、Agent 框架或 NumPy。开发回归默认 model=None，评测输出中的召回率取最终引用，拒答清空引用也会降低召回。

两套既有题集用于开发回归，部分规则使用开发反馈完善，不是独立泛化证据。报告不评价法律回答正确性，也不与旧版不完整 RAGAS 评分合并。实际结果见 [评测目录](../evaluation/results/README.md)。
